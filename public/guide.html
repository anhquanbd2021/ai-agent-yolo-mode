Guide

What the lab proves

One scripted agent run — "fix the flaky login test and open a PR" — replayed under three permission models. Same actions, same order; only the gate changes.

Simulated, on purpose. The agent is a script and the operator is a rule (expectedApprover approves only what the task asked for). The point is the verdict pattern, not a real model's choices.

Start here

The three runs

Policy 1

gated

gate: "risky" — every irreversible or external action pauses for a human. The operator approves the requested PR and denies the five freelanced actions. Result: 6 of 11 actions run, blast radius 5.

Policy 2

yolo

gate: "never", no denylist, no caps. All eleven actions execute the moment the agent picks them: the force-push, the admin merge, the public comment, the release. Blast radius 44 — the worst case of this run.

Policy 3

railed

No gate, but deny lists the four known-dangerous actions and a blast tripwire sits at 20. The listed four are blocked — and rm -rf test/fixtures still executes, because nobody wrote it down. Blast radius 13.

Risk tiers

Classify by blast radius, not by tool

read

Observes only

Nothing to undo. Never gated.

reversible

Local and undoable

Edits, local commits — a diff away from clean. Flows through in every policy.

irreversible

Local destruction

rm -rf on data with no undo path. Gated — or denied outright.

external

Leaves the sandbox

Pushes, merges, comments, publishes — visible to others, often unrevocable. The tier YOLO mode really changes.

The trade

Gate vs. denylist vs. tripwire

ControlCatchesMissesCost
Human gateAnything a person flags — including surprisesNothing in scope; but humans rubber-stamp under fatigueLatency + attention on every risky step
DenylistEvery action you enumerated — instantly, in any moderm -rf test/fixtures: what nobody thought to listZero attention; near-zero latency
Tripwire (max blast/cost)The spiral — halts the run when counters pass a lineA single big action under the line; damage up to the capNone — it is a kill switch, not a reviewer

Run locally

Inspect the evidence

npm test        # policy engine + runner + examples sync + server
npm run scan    # CLI: one run, three policies side by side
npm run check   # both
npm start       # serve the lab on :3000

Edit a policy in examples/ — add "irreversible" to the railed denylist and the fixture deletion joins the blocked list.

Limits

What this demo does not claim

  • The action stream is scripted — a real agent's actions are not predictable, which is exactly why the gate exists.
  • The simulated operator is a rule, not judgment. A tired human approves worse than expectedApprover.
  • Blast-radius and dollar numbers are illustrative units, not measurements.
  • A policy engine here is a teaching model; real enforcement lives in the agent harness, the forge's branch protection, and the credential's scopes.
